# Schema Stream Demo Visual Identity

## Style Prompt

A precise, editorial developer-tool film in the visual language of schema.stream. The viewer
follows one stream as it becomes progressively more useful: raw JSON advances, completion events
resolve, policy changes alter cadence, and a release dashboard materializes. Frames should feel
like the documentation product itself scaled for video, with disciplined rules, code surfaces,
small operational labels, and confident motion instead of simulated screen recording.

## Concept Angle

Structure becomes usable before the response is finished: one blue progress signal travels from
incoming text to events, policy, and a complete interface.

## Colors

- Canvas: `#f7f7f5`
- Panel: `#ffffff`
- Ink: `#111111`
- Secondary: `#3d3d3d`
- Muted: `#646464`
- Rule: `#dddddd`
- Code surface: `#101010`
- Code text: `#f4f4f4`
- Blue focal accent: `#0057d9`
- Green completion accent: `#08783e`
- Amber pending accent: `#9a5b00`

## Typography

- Display and UI: Geist Sans, variable weight, embedded from `assets/Geist-Variable.woff2`
- Code and metadata: Geist Mono, variable weight, embedded from
  `assets/GeistMono-Variable.woff2`
- Headlines use strong weight contrast; data and operational labels remain monospaced.

## Motion

- Deterministic 16-second, 1920x1080 composition at 30 fps.
- Entrances are crisp and directional with varied easing; no uniform fade-up choreography.
- A blue progress line, cursor, or selected-policy state is the recurring focal signal.
- Scene changes use full-frame structural wipes or crossfades; outgoing scenes remain intact.
- Ambient motion is restrained to scanning rules, caret pulses, and slow grid drift.

## Foreground Density

Every scene carries at least eight visible elements across three layers: a subtle grid or rule
system, the primary code/event/dashboard content, and foreground metadata such as snapshot counts,
paths, timestamps, policy labels, or registration marks. Content is edge-anchored and uses at least
two focal points.

## What Not To Do

- No gradients, glows, bokeh, or decorative orbs.
- No fake browser window, mouse wandering, or screen-recording cursor choreography.
- No generic equal-card grid or oversized rounded containers.
- No tiny web-scale typography, negative letter spacing, or text that depends on hover.
- No claims about universal speedups or comparisons to unrelated JSON operations.
